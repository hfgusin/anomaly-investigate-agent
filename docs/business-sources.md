# 业务来源目录

第一版用 Skill 约束核对流程，用 Python 只读工具检索人工来源记录，没有建立向量索引。

## 入口与行为

- 网页输入 `/source-lookup 渠道没开启应该查哪里` 或 `/source-lookup PHLOCAL 非主店广告操作查哪里`。
- 开启意图路由时，自然语言来源问题可选中 source-lookup；这是模型分类，未做真实模型准确率验收。显式命令可以跳过分类。
- 工具 `search_business_sources` 每次读取根目录 `script_and_data_info_record.md`，返回候选及记录序号。无命中返回空数组，文件损坏或字段类型错误返回工具错误。
- 按空格拆分关键词，不区分大小写，任一词命中任务名、ID、描述、别名、表名或脚本即入选。完整字段匹配优先，其次按命中词数排序；同分保留原文顺序。默认返回 5 条，最多 20 条，`total_matches` 表示全部命中数。不提供语义相似度或可信概率。
- daily-check 也可调用目录工具定位候选。source-lookup 仅开放目录检索、本地源码读取和需网页审批的只读 DI SQL。没有增加业务写权限。

## 如何维护

直接维护 `script_and_data_info_record.md`，不需要另建目录或重建索引。文件名虽然是 Markdown，内容必须是合法 JSON 数组。每条记录必需 `taskId`（整数或 null）、`taskName`、`projectCode`；其他旧元数据可以保留，工具不返回旧任务状态或更新时间。

可选字段如下，未知字符串字段用 null，未知数组用 []：

| 字段 | 含义 |
|---|---|
| description | 用来回答哪些问题、数据能说明什么 |
| relateScript | 已知关联脚本路径；保留原路径，不自动假设服务器映射 |
| aliases | 常见业务叫法或关键词数组，例如 `["渠道没开", "渠道开启"]` |
| tableName | 经核对的完整表名，与 taskName 分开 |
| regions | 已确认的适用站点数组 |
| dateColumn | 已确认的业务时间字段 |
| timezone | 已确认的业务时间时区 |

工具用 Pydantic 校验字段类型；类型通过不代表业务内容已经核实。目录描述只用于来源选择，不能证明实际操作成功；描述里的执行时段不能代替实际运行日志。查询数据前仍要确认表名、字段、商品/站点及日期。当前未接入 DataMap/DataHub 发现工具，缺失信息只能沿已知源码核对或请用户补充，不按任务名猜表名。

## 手动验收

启动更新后的 Gateway，在网页新建对话：

1. `/source-lookup 渠道没开启应该查哪里`：Trace 应出现 `search_business_sources`，关键词含「渠道」或「开启」，返回渠道全量开启记录及脚本；回答引用原文件和记录序号，不声称查过实际操作。
2. `/source-lookup PHLOCAL 非主店周二的操作查哪里`：应返回 PHLOCAL 来源，不能改查 scs_take_rate_ads 固定日志表；未知表名、站点和时间字段列为待确认。
3. `/source-lookup 查询不存在的来源 XYZ_UNLISTED_9381`：用该标识检索应无匹配，回答只说目录未匹配，不能声称数据库没有记录。
4. 给某条记录补一个独有 aliases 值，下一次查询这个值应命中，无需重建索引。

对照网页 Trace 的工具参数、结果和最终回答核验。自动测试覆盖本地检索、目录失败、Skill 选择与权限；这些测试不代表真实模型一定能选对来源或完成业务 SQL 查询。
