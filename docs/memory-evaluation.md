# 会话 Memory：当前评测边界

## 目标与判定

测试问题是：早期事实被上下文预算裁掉后，运行时能否保存来源、生成可用摘要，并让后续回答准确引用该事实。自动用例使用固定模型桩检查状态迁移；`scripts/qa-memory-live.mjs` 使用 `.env` 中配置的真实接口、随机 `Amber-*` 代号和临时 SQLite 数据库。脚本结束会删除临时数据库。

真实接口脚本要求同一轮同时满足：Run 为 `completed`；摘要状态为 `completed` 且版本为 1；摘要含随机代号并引用写入代号的 Run ID；最终回答去掉首尾空格后恰好等于代号；消息与预留空间不超过字符预算。它检查可观察输出，不验证模型内部推理。

## 已观察结果

| 检查 | 结果 | 范围 |
|---|---|---|
| 自动回归 | 46/46 通过 | 包含多事实摘录、旧指令过滤、来源错配、旧缓存重建、摘要回退、进程重启恢复、无工具文本帧兼容 |
| 真实接口，当前修复后 | 连续 3 次通过旧事实 → 超预算 → 摘要 → 精确回答 | 每次代号随机；均为同一种简单事实场景 |
| 修复前真实接口 | 观察到摘要可用但最终 Run 失败 | 接口在结束帧返回空 `tool_calls` 或重复相同结束标记；适配器已允许这两种无内容的结束帧，并有回归用例 |
| 摘要失败回退 | 自动回归通过；真实接口曾回答正确 | 摘要失败时使用摘录，不能据此认定摘要质量通过 |

## 下一组质量场景

运行 `node scripts/qa-memory-cases.mjs` 会分别建立临时会话，检查事实更新、助手误记后的用户纠错、明确标记的待分析文本、两个较晚事实、以及未标记的旧指令。每组同时输出 `summaryAcceptedWithFact`、`summaryRejectedSafely`、最终精确回答和字符预算；脚本成功表示本轮有安全的 Memory 路径且最终答对，**不表示五组摘要都生成成功**。

当前五组最终复测中，五组最终回答均精确正确、预算检查通过；事实更新、助手纠错、两个较晚事实和未标记旧指令四组使用了摘要；明确标记的待分析文本一组中，模型把代号引向了不支持该代号的 Run，校验拒绝摘要并使用摘录，最终仍答对。这是一次运行的结果；此前运行中摘要也曾因缺少完整来源 ID 或过长而回退。仅靠额外模型审核会误拒正确摘要、放过污染摘要，因此没有保留这道审核。

当前提取规则会跳过明确标为“供分析／待分析／恶意文本／测试文本／引用文本”的历史轮次，也跳过部分明确要求改变以后回答方式的旧指令；原始 Run 仍在 SQLite。摘要中的代号类标识符会与引用的原始 Run 内容对照，错配时拒绝摘要。规则只覆盖这些可识别的形式；重要事实恰好写在被跳过的轮次、其他语言或写法的注入、以及复杂多轮事实矛盾仍需单独评测。模型摘要仍可能生成不完整引用并触发回退。

Memory 快照的 `policyVersion` 用于缓存迁移：旧规则生成的摘录和摘要在下次使用时重建，避免旧摘要绕过新校验。自动回归覆盖了这个迁移。摘要校验只对代号等可识别的标识符做来源匹配，普通自然语言仍没有通用的事实蕴含验证。

## 仍未证明

- 来源 Run ID 的检查只能确认 ID 属于摘录，不能证明摘要中每句话都由该 Run 支持。真实接口脚本额外要求代号对应的 Run ID 出现在摘要，但这仍不是通用事实一致性评测。
- 摘录最多保存 2048 字符；按最近、最早交替选取，每轮先保存至多 180 字符的用户内容，再补至多 160 字符的助手内容。历史很多或单条事实很长时可能遗漏。快照只登记实际选入的 Run ID。
- 当前是会话内 Memory。没有跨会话检索、自动后台摘要 worker、真实 token/cost 计量或长期成功率数据；字符预算也不保证实际模型 token 数。
- 真实接口仍是每种场景少量随机运行，没有长期成功率数据。下一组要扩展不同语言、改写过的旧指令和非代号类事实，并分别统计摘要成功率、回退率及最终回答准确率。
