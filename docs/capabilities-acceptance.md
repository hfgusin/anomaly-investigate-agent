# 多类型能力：页面验收

启动 `pnpm dev`，打开 `http://127.0.0.1:18789` 并新建会话。空会话有四个按钮；按钮只填入输入框，点击「发送」才会请求模型。每次模型实际请求工具后，页面会展示工具名与参数，必须点击「允许这次」才执行。审批后可以展开「运行记录」查看工具结果和状态。

1. **查看文件**：点击「查看文件」并发送。若模型调用 `list_workspace`，批准后应看到 `agent_demo.txt`。运行记录应是 `requested → approved → completed`，并列出文件名。如果模型没有调用工具，只算普通文本回答。
2. **新建文件**：点击「新建文件」并发送。审批框应展示路径、内容和 `mode=create`。批准后检查 `workspace/tonight-note.txt` 确实存在、内容正确。再用同样请求尝试创建一次，应得到“文件已存在”，不会覆盖。若想测拒绝，先换一个文件名，在审批处点击「拒绝」，确认文件没有出现。
3. **读取网页**：点击「读取网页」并发送。批准 `fetch_url` 后，运行记录应包含最终 HTTPS URL 与正文摘录，回答应基于该内容。当前开发终端不能解析公共域名，所以网页能否成功需要在你的网络环境下验收；工具失败不能写成“没有找到资料”。
4. **代码默认关闭**：「代码执行未启用」按钮应不可点击。手动发送“必须调用 run_javascript 执行 console.log(2 + 3)”：模型可能直接解释不可用；若模型强行调用，工具记录应为 `blocked`，不能出现“允许这次”或实际执行。不要为了验收这一条打开代码开关。

以上四条分别验证模型是否选择工具、你是否看到了准确参数、批准后工具是否执行、模型是否使用实际结果。工具直调通过或 TypeScript 构建通过，都不能替代这四条页面验收。

当前 `plain` 模式每个 Run 只允许一轮工具调用。若要同一 Run 内连续“读文件 → 修改文件”或“查网页 → 写总结”，需要模型支持标准工具结果消息，并设置 `MODEL_TOOL_RESULT_MODE=standard`。写文件和运行代码在进程中断后不会自动重放。
