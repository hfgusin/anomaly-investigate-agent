# P0～P13 总路线图

核对日期：2026-10-01。目标参考版本：OpenClaw v2026.9.6。

本文件是当前进度与后续顺序的统一入口；[工作记录](status.md) 保留历史过程，[P0 对照](parity.md) 保留原版观察。长任务属于 P2，Web/CLI 属于 P11，不再为局部开发阶段重用 P 编号。

## 验收口径

- **已实现**：当前代码具备所述能力，不自动代表模型效果、用户验收或原版兼容。
- **工程验证**：受控模型/工具、集成及故障注入；报告明确输入、断言和可用 Trace。
- **真实模型验证**：注明题目范围与结果，不能从少量样例推断总体正确率。
- **用户验收**：用户亲手操作确认；代理浏览器检查单独记录。
- **原版对照**：固定版本、固定场景的具体观察；未观察的行为不记为一致。
- **延期**：明确保留的缺口，不能从整版验收范围中静默删除。

目前没有证据支持“全部达到原版整版验收”。以下是能力范围矩阵，尚不是 v2026.9.6 全功能逐场景清单；该清单仍属于 P13 待办。

## 证据快照与质量边界

1. P4 更新后重新执行 `pnpm verify`：117/117 通过，一轮。报告为 `.data/verification/latest.json`，含时间、源码哈希和逐例结果；该路径会被后续运行更新。本次未重新调用真实模型或原版。
2. 既有固定 10 题真实 Gateway 配对：`/research` 完成 7/10、联合 EM 3/10；`/research2` 完成 9/10、联合 EM 2/10。早期 CLI 的 1/10 是另一轮历史结果。详见 [研究第二版](next-milestone.md)。
3. 既有 Multi-Agent 两题：支持事实精确匹配 2/2、答案精确匹配 1/2；原始记录 `.data/multi-agent/live-check.json`。父子链路完成不代表所有答案正确。
4. 研究使用 HotpotQA 原题对应的十篇候选文章，不是实时全网检索；标准答案用于评测，不作为研究工具结果送入模型。
5. 工程通过、模型质量、用户操作确认与原版一致性分别记录，不合并成一个完成率。

## 保留的延期与待验收

- **按用户要求延期**：鉴权及会话权限；直接向正在执行的模型请求注入引导（当前取消请求并重启同一 Run）。
- **用户待验收**：Multi-Agent 派发/孩子审批、单子停止与父停止、恢复和结果出处；步骤见 [Multi-Agent](multi-agent.md)。
- **多类型工具待验收**：写入审批及结果核对、公网获取、显式开启后的可信代码实验；步骤见 [能力验收](capabilities-acceptance.md)。默认不因验收而开启代码工具。
- **质量待改进**：研究答案/证据一致性、摘要质量；不以工程用例数代替正确率。

## 后续顺序与完成条件

这是后续实施顺序，不表示这些功能已经交付；文档收口后已实施第 2 项的第一版，其余为后续计划。

1. **文档收口（本次）**：统一总编号，链接证据，纠正旧快照；保留 P0 已有观察，不重复宣称全部未测。
2. **P4 Skill 发现与刷新（代码已实现，用户验收待完成）**：定义目录和优先级；新增/修改 Skill 后下一次运行生效，当前运行保留已选版本；坏文件给出明确错误，来源和版本可查。用户用一个新 Skill 和一次修改参与验收。
3. **P8 自动化第一版**：持久化计划、触发记录和去重键；重启后按明确补跑策略处理到期任务；工具审批仍有效，执行结果不确定时不得盲目重放副作用。用户创建一项任务并观察触发、重启及取消。
4. **P7 一个外部渠道**：确定具体渠道及凭据后接入；验收收发、会话映射、重复消息和断线恢复，再扩展其他渠道。
5. **P1 原版协议兼容**：从固定版本提取握手/RPC/session key/事件场景，以原版客户端连接和恢复验证。鉴权延期仍是完整验收缺口，不能将自定义客户端跑通记为原版兼容。
6. **P13 持续收口**：每项实现关联原版场景、当前证据、差异和待验收状态；P3/P5/P9/P10/P11/P12 剩余项继续保留，未完成项未清零前不宣布完整复刻。
