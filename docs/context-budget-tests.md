# Context 预算：验证记录

当前实现以字符估算上下文大小，不把它称为模型真实 token 数。不同模型的 tokenizer 不同；接入模型专用 tokenizer 前，运行记录中的数字只用于稳定地执行本地预算策略。

| 检查 | 结果 | 证据 |
|---|---|---|
| 当前问题始终保留 | 通过 | `contextFor` 先预留当前问题与引导；自身超过预算时明确失败 |
| 整轮裁剪 | 通过 | 自动检查构造两段历史，只保留最新完整的 user/assistant 对，最旧轮次不进入模型请求 |
| 审计持久化 | 通过 | 同一自动检查断言 `contextTrace` 被写入 SQLite |
| 连续历史 | 通过 | 较新的大轮次超预算后，更早的短轮次也不会重新进入上下文；快照覆盖连续的最旧历史 |
| 真实页面显示 | 通过 | 真实接口 Run `1bc84aeb-3790-4761-9cb6-34d42131536b` 显示 `11/120000`、保留 0、裁掉 0 |

当前会为被裁掉的连续历史保存有界摘录，并尝试生成包含固定字段的摘要；原始 Run 始终保留。摘录先取较新、再取较早轮次的用户内容，最后补助手内容，避免一段大输出占满空间。明确标记的待分析文本和部分针对未来回答的旧指令不进入摘录。摘要必须含来源 Run ID，代号类标识符要在引用的原始 Run 中出现，且摘要不超过预留字符数；失败时使用摘录。状态持久化在 SQLite：`pending`、`generating`、`completed`、`failed`。进程重启会把 `generating` 恢复为 `pending`，下一次使用该快照时重试。`policyVersion` 变化时旧快照会重建。

真实接口检查：运行 `node scripts/qa-memory-live.mjs`，使用临时数据库中的随机 `Amber-*` 代号和超预算填充历史，检查摘要、事实来源 Run ID、预算与精确回答。先前一次运行暴露了模型忽略单独历史消息的问题；将历史放在当前问题旁后，模型正确回答。另有摘要失败后摘录回退答对的观察。当前协议适配修复后连续 3 次完整通过；详情和未证明范围见[Memory 评测](memory-evaluation.md)。
