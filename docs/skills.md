# P4 Skill 发现与刷新第一版

## 使用方式

在项目根目录创建 `skills/<名称>/SKILL.md`，名称使用小写字母开头的字母、数字和连字符（最多 64 字符）。文件正文就是模型指令，不要求 YAML 配置。命令为 `/<名称> 任务内容`。当前没有自动语义选择或 YAML 元数据解析。

- 项目目录 `skills/`：可以随项目保存。
- 本机目录 `.data/skills/`：同名 Skill 覆盖项目版本；删除覆盖文件夹后恢复项目版本。此目录默认不入库。
- 原有 `multi-hop-research`、`multi-hop-research-v2` 仍对应 `/research`、`/research2`，保持既有研究工具与校验流程。
- `new/reset/stop/team/research/research2` 名称保留。新 Skill 使用普通工具权限，不会因此绕过审批或启用代码执行。
- 目录与 SKILL.md 不允许符号链接；每个根目录最多 64 个条目；正文非空、最多 8000 字符，文件最多 32000 字节。非隐藏的子目录都必须有有效 SKILL.md。

这些是可信本机指令目录，位于模型可写的 `workspace/` 之外。不要把外部资料自动复制成 Skill。

## 刷新与快照

新 Run 使用斜杠命令时扫描目录，包括排队后才开始的任务；普通聊天不扫描 Skill。页面左下角 **Skills → 刷新目录** 可以提前检查；`skills.list` 读取现有目录快照，`skills.refresh` 执行扫描。页面显示来源、完整内容 SHA-256 和刷新时间。

刷新按 Skill 隔离错误：坏文件从可用列表排除，页面 errors 列出名称与原因，调用该 Skill 返回 `SKILL_INVALID`。其他有效 Skill 和普通聊天继续工作；坏的本机覆盖不会静默回退项目旧版。根目录读取失败仍返回 `SKILL_REFRESH_FAILED`。修复后刷新恢复。

首次选择把完整内容、来源、命令和版本保存到 Run 的 `skillSnapshot`；即使没有选择 Skill，也保存 JSON null。运行中修改文件、引导重启同一个 Run，以及支持恢复的任务重启，都沿用已保存快照。普通任务的恢复范围没有扩大。升级前未保存快照的旧任务在下一次执行时才选择并保存，无法追溯旧文件内容。

删除整个自定义 Skill 文件夹后，新任务不再选择它；只删除 SKILL.md 留下文件夹会报错。未知斜杠命令返回 `SKILL_NOT_FOUND` 并列出可用 Skill，不再静默转成普通聊天。删除内置研究 Skill 后，对应研究请求明确失败。

## 你可以亲手验收

先用 `pnpm dev` 重启一次以加载本次代码，并刷新网页；之后修改 Skill 文件无需重启服务。

1. 新建 `skills/brief/SKILL.md`，写入：

   ```text
   将用户提供的内容总结为两条中文要点。回答第一行必须为：BRIEF-V1。
   ```

2. 页面打开 **Skills → 刷新目录**，应出现 `/brief`、`skills/brief/SKILL.md` 和 SHA-256。发送：

   ```text
   /brief 今天完成了工具审批和会话恢复，明天处理定时任务。
   ```

   预期回答有 `BRIEF-V1` 和两条要点；运行记录有 Skill ID、版本和来源。模型不遵循格式时，分别检查是否加载正确和是否遵循指令。

3. 等本次任务结束，将文件中的 `BRIEF-V1` 改为 `BRIEF-V2`，发送一条新的 `/brief` 请求。无需重启，预期新版本哈希不同、新回答使用 V2；旧 Run 的快照仍为 V1。运行中直接发送会成为“引导”，仍使用该 Run 的旧快照。
4. 在 `.data/skills/brief/SKILL.md` 写入同类指令但标记为 `BRIEF-LOCAL`。刷新后来源应变为本机目录，新任务使用 LOCAL；删除 `.data/skills/brief/` 整个目录后，新任务恢复项目 V2。
5. 将文件临时清空并刷新：应显示明确错误；修复内容再刷新后恢复。不要把错误状态下保留的旧目录当成刷新成功。
