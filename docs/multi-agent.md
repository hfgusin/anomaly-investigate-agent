# Multi-Agent 第一版

本版已接入真实 Runtime、SQLite、Gateway 与 Web。`/team` 路由到协调 Agent；模型调用 `delegate_task` 批量派发，用户批准后才创建子任务。普通对话与现有研究指令保留原入口。

## 配置与执行

`config/agents.json` 配置角色提示、工具列表、超时、每角色并发数，以及全局并发和每父任务子任务数。Web 左下角「Agent 配置」显示生效值。修改后重启；每个 Run 保存角色配置快照，恢复沿用原角色与工具范围。共用已有模型接口与额度；协作运行使用标准 tool 消息格式。

默认全局最多同时运行 2 个孩子，每个父任务最多 4 个孩子，一层派发：

- `reader`：列出、搜索和读取工作区文件，读取 HTTPS 网页；只有只读工具。
- `researcher`：执行 HotpotQA 数据集中存在的完整原题，使用 `search_passages` 与 `open_passage`；沿用两跳检索、证据校验和一次修正。
- `main`：只派发子任务与汇总。孩子的输入是明确分派的内容，不继承父会话历史。子任务不能再派发、写文件或执行代码，配置也不能启用这些能力。

派发参数示例：

```json
{"tasks":[
  {"key":"read-note","agentId":"reader","input":"读取 agent_demo.txt，概括其中的信息并说明来源。"},
  {"key":"list-files","agentId":"reader","input":"列出工作区根目录的文件。"}
]}
```

同一父任务的 key 是派发幂等键：相同 key、Agent 和输入复用原 Run；换内容报冲突。整个批次在一个数据库事务内校验和创建，不留下半批任务。每个孩子有独立内部 Session 与 Run；内部会话在父卡片下展示，不能直接追加用户消息。

父模型 HTTP 响应结束后才进入派发和等待，不占用模型 HTTP 并发名额。孩子的执行名额从开始到结束保持占用，包括等待工具审批；超出全局或角色并发数的孩子排队。执行预算不包含人工审批等待，父任务在孩子等待审批时也暂停执行计时；连续审批等待上限 10 分钟，单次运行总期限 30 分钟。排队孩子仍受到父任务期限约束。进程重启恢复后计时重新开始；不是跨进程累计的截止时间。模型接口额度另由共享 limiter 约束。

## 结果、停止与恢复

回传包含 `runId/key/agentId/status/outcome/answer/failureCode/toolErrors/evidence`。`status=completed` 仅表示执行结束；研究回答“证据不足”会转成 `outcome=insufficient_evidence`，`answer=null`，父任务收到明确原因。失败或取消的部分输出保留在子 Run 中，不作为成功答案回传。每个答案最多回传 2000 字符，证据最多末尾 4 条、每条 500 字符，截断显式标记；完整内容仍保留在子任务详情。

父回答须引用实际孩子的 `[child:完整RunID]`。漏掉孩子或引用虚构 ID 会使父任务失败。没有实际派发就声称完成也会失败；用户拒绝派发可以正常结束并说明未执行。引用检查只验证来源关系，不证明模型结论正确。

停止父任务先持久化父终态，再取消运行中和排队中的孩子；停止单个孩子会把取消状态回传，其他孩子可以继续。已开始的协作任务不接受 steer，避免重新生成重复派发。

重启时重建原父子关系；已完成孩子不重跑，未完成只读孩子恢复。工具结果落库后复用；未落库的只读操作可能重试。待审批仍然待审批，不自动批准。父模型从保存的子任务结果重新生成，网络流不原地续传，可能产生额外模型费用。如果强杀发生在父停止落库、子停止之前，恢复器取消遗留孩子。多 Agent 第一版不运行有副作用的子任务。

## 你可以参与的页面验收

重启 `pnpm dev`，新建会话，点击「协作研究」示例，或输入：

```text
/team 请派发两个 reader 子 Agent：第一个读取 agent_demo.txt 并概括，第二个列出工作区文件。等待二者完成后汇总，并引用每个子任务。
```

1. 父任务先显示 `delegate_task` 审批，参数包含两个任务。批准后显示两张子卡片。
2. 分别批准孩子的只读工具；查看各自结果。父回答应引用两个真实孩子 ID。
3. 新建一轮，派发三个 reader；让前两个停在审批，第三个应排队。停止父任务后，三者都停止。
4. 让一个孩子完成，另一个停在审批；关闭并重启服务。刷新后孩子 ID 保持相同，完成结果保留，另一孩子仍需你审批。
5. 点「子任务详情与出处」查看独立步骤和证据。左下角「Agent 配置」查看角色工具与并发数。

HotpotQA 演示可使用两道已有原题：

```text
/team 在一次 delegate_task 中派发两个 researcher，分别处理以下原题，再汇总并引用每个子任务和资料出处：
1. The director of the romantic comedy "Big Stone Gap" is based in what New York city?
2. What film directed by David Greene did Merrell Jackson play an apostle in?
```

需要已下载的完整 `.data/hotpotqa/validation.json`；仓库自带的 `validation-sample.json` 只有另一道题。第一版仍在每道题自带的候选文章中检索，不是开放网络搜索。

## 已验证与边界

最新统一验收为 106/106 通过，其中新增 13 个 Multi-Agent 专项和 1 个 Gateway 父子审批用例。自动用例位于 `tests/multi-agent.test.mjs` 和既有 Gateway 测试，覆盖全局/角色并发、上下文隔离、幂等与批次原子性、工具范围、级联停止、超时失败回传、恢复审批、孤儿取消、真实 SIGKILL，以及模型仅有一个 HTTP 名额时父等待不阻塞孩子。统一报告仍使用 `pnpm verify`，没有另建独立评测命令。

真实模型使用上述两道公开题，在独立数据库 `.data/multi-agent/live.sqlite` 执行。父任务和两个孩子完成；分别执行 4 次与 3 次资料工具调用。支持事实精确匹配 2/2，答案精确匹配 1/2：第一题只答 Greenwich Village，标准答案更完整；第二题 Godspell 匹配。父任务保留子任务引用。原始记录与评分在 `.data/multi-agent/live-check.json`，标准答案只用于运行后的评分，未送入模型。

首次验收启动用了 `--input-type=module`，Worker 继承该参数导致启动失败；原记录保留在 `live-check-launch-error.json`。改为正常 Node 启动后跑通。不能将首次“证据不足”的结束状态当作问答成功。

代理已通过独立预览服务检查真实结果的父子卡片、子任务步骤、两篇资料出处和 Agent 配置面板。用户亲手确认尚待进行。当前是本机、单进程、一层只读协作；没有跨机器调度或每 Agent 独立模型端点。
